01 / INSTALL

Choose your Windows build.

Nexus 0.2.1 is a Windows x64 preview. Windows 11 is the primary tested platform; broader Windows 10 and mixed-DPI validation is pending.

The installer creates a Start-menu shortcut and an Installed Apps entry for the current user. It requests no administrator elevation and does not add an automatic startup entry. The portable ZIP contains the executable and license; extract it before running.

Both builds include .NET. The original CursorBlur engine additionally needs Microsoft’s Visual C++ v14 x64 runtime; a missing runtime shows a help link.

An unsigned preview

The build has no Authenticode publisher signature. Review the release notes and compare the supplied SHA-256 hashes. Hashes confirm file matching, not publisher identity.

02 / PERMISSIONS

Let each tool earn its place.

Every module begins disabled. Open Permissions and review the capability a feature needs: mouse, keyboard, screen capture, clipboard, window control or optional network access.

“Blocked” means a module is enabled but missing a required grant. Grant the relevant access to start it. These are Nexus’s own capability controls, not an operating-system sandbox for third-party native code.

Screen capture cannot access protected video or secure desktop. Some elevated applications reject input or window changes from an unelevated utility.

03 / YOUR FIRST MODULE

Pick one useful change.

Open the module library and enable a feature. Features with settings offer Configure; CursorBlur has direct enable/disable/uninstall actions. Shared family code remains in the unified executable.

For ScrollFlow, exit standalone Glide first. For CursorBlur, exit a standalone copy and enable the module; it runs the bundled original executable with no Configure screen. Its timing and motion are independent of Nexus’s WPF controls. For Nexus-rendered overlays, select a 60–240 FPS target in Settings and inspect the measured rates. A target is not guaranteed presentation performance.

04 / YOUR WORKSPACE

Keep the choices that work.

Set module toggle shortcuts on Hotkeys. Nexus reports conflicts with shortcuts already owned by Windows or another application. Some feature-action combinations remain fixed in this preview. Use Settings & updates → Check for updates → Download and install to update in place with your settings kept. The official signed feed and key are included; Network permission is required and daily checks are optional.

Save a named profile to preserve your module choices and options. Import and export use JSON and do not include clipboard contents or permission grants. Transfer is manual; live/cloud sync is not implemented.

05 / TROUBLESHOOTING

When something feels off.

A module says Blocked

Review its required grants on Permissions. Enabling a feature alone does not grant capture or system access.

ScrollFlow will not start

Exit standalone Glide. Nexus avoids running two scrolling engines together. The feature’s settings panel reports the native touchpad or wheel backend, current routing status and any output error.

An overlay looks slow

Check the target and measured rendering rate in Settings. Reduce simultaneous effects or capture size when the GPU/CPU is busy. Monitor refresh and capture cost affect output. Reduced motion also changes or suppresses effects deliberately.

Window opacity stayed behind after a forced exit

Normal disable/exit restores supported window attributes. A crash or forced termination cannot guarantee cleanup. Restarting the affected third-party application restores its own normal window state.

Closing the hub did not stop Nexus

The app remains in the notification area. Choose Exit Nexus from its tray menu to release hooks, overlays and timers.

06 / REMOVAL

Leave your setup intact.

Exit Nexus through its tray menu, then use Windows Settings → Apps → Installed apps → Nexus → Uninstall. Your local settings are retained in %LOCALAPPDATA%\Nexus.

Installed program files live in %LOCALAPPDATA%\Programs\Nexus. Portable and installed copies share the same per-user settings and cannot run together. In-app feature removal resets that feature’s configuration and resources, while shared code stays in the app.
